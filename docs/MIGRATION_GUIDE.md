# Руководство по миграции: Старая структура → Новая структура

## Что изменилось

### Старая структура (v3.1)
```
LocalGitMirror/
├── core/              # Логика backend
├── routers/           # API endpoints
├── main.py            # Точка входа
├── frontend/          # Vue приложение
└── *.md               # Документация везде
```

### Новая структура
```
LocalGitMirror/
├── run.py             # канонический лаунчер (prod/dev)
├── backend/
│   └── app/
│       ├── core/      # Бизнес-логика
│       ├── routers/   # API endpoints
│       └── main.py    # FastAPI приложение
├── frontend/          # Vue приложение
├── idea-plugin/       # IntelliJ-плагин DocCache
├── lgm_core/          # движок CLI/MCP
├── docs/              # Вся документация
└── README.md
```

## Преимущества

✅ **Чистое разделение** - Frontend и backend изолированы  
✅ **Стандартная структура Python** - Следует лучшим практикам  
✅ **Лучшие импорты** - `from app.core.logger import get_logger`  
✅ **Масштабируемость** - Легко добавлять новые модули  
✅ **Организованная документация** - Вся документация в `/docs/`

## Шаги миграции

### 1. Обновление пути Python

Весь код бэкенда теперь импортируется с префиксом `app.` (`backend/app/`). Лаунчер обрабатывает пути сам, вручную `PYTHONPATH` настраивать не нужно.

### 2. Запуск приложения

**Старый способ:**
```bash
python main.py
```

**Новый способ (из корня репозитория):**
```bash
python run.py            # прод: HTTPS + собранный SPA
python run.py dev        # разработка: backend --reload + Vite
```

Лаунчер сам создаёт `backend/venv`, ставит зависимости из `backend/requirements.txt` и перезапускается внутри этого venv. Активация venv и `cd backend` не нужны.

### 3. Изменения импортов

Все импорты теперь используют префикс `app.`:

**Старый:**
```python
from core.logger import get_logger
from routers.api import router
```

**Новый:**
```python
from app.core.logger import get_logger
from app.routers.api import router
```

### 4. Переменные окружения

Файл `.env` остаётся в корне проекта (изменения не требуются). Порты берутся оттуда: `WEB_PORT` (по умолчанию 443), `GIT_PORT` (8444), `REDIRECT_HTTP_PORT` (по умолчанию не задан).

### 5. Путь хранилища

Путь хранилища задаётся в `.env` (`STORAGE_PATH`, по умолчанию `storage/`). Смена пути через настройки или `POST /api/config/storage` требует перезапуска сервера.

## Тестирование миграции

1. **Остановите старую версию** (если запущена)

2. **Запустите новую версию** из корня репозитория
   ```bash
   python run.py
   ```
   Зависимости установятся автоматически при первом запуске.

3. **Проверьте**
   - Откройте `https://localhost` (порт из `WEB_PORT`; сертификат самоподписанный, браузер предупредит)
   - Проверьте браузер файлов и настройки в SPA
   - Проверьте работу логов

## Очистка старых файлов

Файлы старой структуры (`core/`, `routers/`, `main.py` в корне) удалены; история живёт в git.

## Распространённые проблемы

### Ошибки импортов

**Ошибка:** `ModuleNotFoundError: No module named 'app'`

**Решение:** Запускайте из корня репозитория через лаунчер:
```bash
python run.py
```

### Проблемы с путями

**Ошибка:** `FileNotFoundError: storage/`

**Решение:** Путь хранилища берётся из `STORAGE_PATH` в `.env`. Лаунчер переходит в корень репозитория перед запуском, относительные пути резолвятся от него.

### Порт уже используется

**Ошибка:** `Address already in use`

**Решение:** `run.py` завершает только своё предыдущее дерево процессов; если порт занят посторонним процессом, освободите его вручную или смените `WEB_PORT` в `.env` (и прокси в `frontend/vite.config.js`, если работаете в dev).
